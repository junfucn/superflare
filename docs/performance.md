# 性能排查与优化记录

日期：2026-11-14。对比基线：`800f75e`，以下结果来自同一台机器上的修改前后测量。

## 定位结果与修改

使用现有 `BenchmarkHomePageRender`，通过 Go CPU 和内存分配采样定位首页请求的开销。主要问题和对应优化如下：

- **重复分配页面拼接内存**：`strings.Builder.Reset()` 会释放底层切片，原来的对象池无法复用页面拼接所需的存储。应用、目录弹窗、书签和收藏改用 `bytes.Buffer` 池，返回 HTML 时复制成独立字符串。单个缓冲容量超过 1 MiB 时不再归还池中，避免长期保留异常大的页面。
- **响应缓冲重复复制**：Echo 的 `Context.Render` 每次新建响应缓冲，而项目的 renderer 也先缓冲再复制。公开页面改用 `templates.Render`，复用一个响应缓冲，并在模板成功执行后发送 HTML。模板错误仍交给错误处理器，避免输出半个页面或提前提交成功状态码；自定义 renderer 仍受支持。
- **每个分类扫描全部书签**：渲染前一次性按分类分组，将分类匹配从 O(分类数 × 书签数) 降为 O(分类数 + 书签数)。分类、子目录和条目顺序保持原有规则，过滤私有项目后再分组。分类内直接输出 HTML，取消每个分类的中间 HTML 字符串。
- **图标存在性检查复制整张图片**：内存缓存增加 `Contains`，页面仅查询缓存状态时不再调用会复制图片字节的 `Load`。实际读取图片仍返回副本，并保留过期清理和容量统计。
- **高频图标地址计算**：失败冷却查询对常见长度的 URL 直接查表，避免每次生成 SHA-256 和十六进制字符串。长 URL 继续使用摘要，键长度保持有界；记录时复制字符串，避免保留更大的原始请求。
- **多余的集合分配**：收藏列表按实际收藏数量分配；首页 SEO 条目合并按最终上限预分配，避免反复扩容。

## 基准结果

环境：Windows/amd64，Go 1.26.4，AMD Ryzen 7 9700X，默认 `GOMAXPROCS=16`。每个基准前后各运行三次，下表分别取耗时、分配字节数和分配次数的中位数。

| 场景 | 修改前 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| 首页：6 个应用、12 个分类、59 条书签 | 0.556 ms/请求 | 0.295 ms/请求 | 耗时降低 47.0% |
| 同场景内存分配 | 565,182 B/请求 | 301,314 B/请求 | 降低 46.7% |
| 同场景分配次数 | 2,060 次/请求 | 1,730 次/请求 | 降低 16.0% |
| 大列表：6 个应用、120 个分类、600 条书签 | 3.439 ms/请求 | 1.340 ms/请求 | 耗时降低 61.0% |
| 同场景内存分配 | 4,222,226 B/请求 | 1,900,138 B/请求 | 降低 55.0% |
| 同场景分配次数 | 12,073 次/请求 | 9,213 次/请求 | 降低 23.7% |
| 64 KiB 内存图标的存在性检查 | 5,947 ns、65,536 B、1 次分配 | 17.88 ns、0 B、0 次分配 | 消除图片复制 |

首页三次耗时范围为修改前 0.403–0.608 ms，修改后 0.287–0.335 ms；大列表分别为 2.351–3.688 ms 和 1.223–1.490 ms。本机调度和 GC 会带来波动，百分比用于描述本组测量。

请求经过真实路由、中间件和模板，通过 `httptest` 执行，缓存预热，禁用请求日志和登录，`Accept-Encoding: identity`。书签均未显式指定图标，使用未下载图标的回退路径；基准不发起外网图标下载。图标内存基准独立测量缓存命中查询。

这些数据反映服务端渲染及其内存分配，不包含实际网络传输、gzip 压缩、浏览器绘制或外部 favicon 站点延迟，不能直接视为用户整页加载时间或并发吞吐量。

## 复现

使用 PATH 中的 Go，或 Windows 仓库自带的 `.tools/go/bin/go.exe`：

```powershell
& .\.tools\go\bin\go.exe test ./internal/server ./internal/fn -run '^$' -bench 'Benchmark(HomePageRender|SiteFaviconMemoryLookup)' -benchmem -count=3
```

新增 `BenchmarkHomePageRenderLarge` 和 `BenchmarkSiteFaviconMemoryLookup`，可在后续修改中复用。
